# 工程项目智能数据中枢——产品整改 PRD

**文档版本**：v1.0  
**制定日期**：2026-07-13  
**文档状态**：待评审  
**目标版本**：Production Ready v1.0  
**适用范围**：Windows 本地桌面版

## 1. 文档目的

本 PRD 用于将当前“功能原型/演示版本”整改为能够在真实工程项目中安装、处理真实文件、产生可信数据、支持安全回滚并可持续维护的本地桌面产品。

本次整改不以“页面存在”或“代码可编译”作为完成标准。所有能力必须通过真实样本、端到端流程和失败场景验收。

## 2. 当前状态判断

### 2.1 产品成熟度

| 领域 | 当前状态 | 主要差距 | 目标状态 |
|---|---|---|---|
| 桌面交付 | 不可稳定构建 | Tauri/SQL 插件版本混用，依赖不可获取 | 全新 Windows 环境可安装、启动、卸载 |
| 文件扫描 | 部分可用 | 忽略目录不生效、符号链接风险、缺少取消 | 可控、可取消、范围准确 |
| 文件去重 | 原型可用 | 保留规则不透明、备份不可可靠恢复 | 操作前可预览，操作后可审计、可恢复 |
| 版本识别 | 演示功能 | 使用模拟数据 | 对真实目录分析并给出可解释结果 |
| 文档解析 | 链路未验证 | 前后端参数不一致、运行环境依赖强 | 支持清单内定义的格式并记录失败原因 |
| AI 抽取 | 实验性质 | 服务启动、模型返回和字段映射不可靠 | 有健康检查、置信度、人工复核和降级策略 |
| 数据库 | 有数据风险 | Schema 重复、REPLACE 破坏关联、无正式迁移 | 单一 Schema、事务、迁移、备份和完整性检查 |
| 看板与风险 | 展示优先 | 失败时自动展示模拟数据 | 只展示真实数据，数据来源可追溯 |
| 测试与发布 | 基本缺失 | 无自动测试、无发布门禁 | 自动化测试、样本验收、版本化发布 |

### 2.2 核心整改原则

1. **真实优先**：生产模式不得静默生成或混入模拟数据。
2. **数据可信**：每个指标能够追溯到来源文件、抽取字段和计算规则。
3. **文件安全**：任何移动、清理操作必须先预览、后执行、留审计、可恢复。
4. **失败可见**：部分失败不得显示“全部完成”，必须提供成功、失败、跳过明细。
5. **离线可用**：除首次可选模型下载外，核心流程不依赖公网。
6. **证据验收**：完成状态必须附构建、测试或真实样本验收记录。

## 3. 产品定位与边界

### 3.1 v1.0 产品定位

面向工程项目经理、商务人员和成本人员的 Windows 本地数据整理工具，从指定项目目录完成：

`安全扫描 → 重复/版本分析 → 文档解析与字段抽取 → 人工复核 → 项目聚合 → 风险展示 → 报告导出`

### 3.2 v1.0 必须支持

- 本地项目目录扫描和文件清单生成。
- 按内容哈希识别完全重复文件。
- 按文件名、版本号和修改时间提供版本候选关系。
- 安全备份、操作清单、原路径恢复和冲突处理。
- PDF、DOCX、XLSX、TXT 的基础解析；图片 OCR 作为可选能力。
- 合同、成本、结算核心字段抽取及人工复核。
- SQLite 本地存储、数据库迁移和数据备份。
- 基于真实数据的项目看板、风险规则和 Word/Excel 导出。
- 可诊断的服务状态、错误日志和处理结果明细。

### 3.3 v1.0 明确不做

- 多人实时协同、云端账户和跨设备同步。
- 自动删除原文件；v1.0 仅移动到应用备份区。
- DWG/DXF 内容解析；仅记录元数据并识别文件名版本。
- 无人工确认的全自动财务结论。
- 将 AI 抽取结果直接视为审计结论。
- macOS/Linux 正式交付。

## 4. 用户角色与核心场景

| 角色 | 核心任务 | 成功结果 |
|---|---|---|
| 项目经理 | 快速了解项目文件、金额、进度和风险 | 能定位高风险项目及其证据文件 |
| 商务经理 | 汇总合同、结算、支付信息 | 关键字段可复核、可导出 |
| 成本人员 | 汇总成本构成和利润偏差 | 数据来源明确，计算规则一致 |
| 系统维护者 | 安装、升级、诊断和恢复 | 无需开发工具即可完成常规维护 |

## 5. 目标用户流程

### 5.1 首次启动

1. 应用检查数据库版本、Python/解析服务和 AI 模型状态。
2. 不可用能力显示明确状态和修复指引，不阻塞仍可使用的功能。
3. 用户创建工作区并选择项目根目录。
4. 应用说明扫描范围、忽略规则和数据存储位置。

### 5.2 主处理流程

1. 用户选择目录并执行预扫描。
2. 系统展示文件总量、类型、预计耗时、不可访问项和忽略项。
3. 用户确认后执行扫描和哈希，允许暂停或取消。
4. 系统生成重复组与版本候选，说明“为何判定”。
5. 用户选择保留文件，查看 Dry-Run 清单后移动重复文件到备份区。
6. 系统解析支持的文件；失败项单独列出并可重试。
7. 系统抽取结构化字段；低置信度或冲突字段进入人工复核队列。
8. 用户确认字段后执行项目聚合和风险计算。
9. 看板仅显示已确认或明确标记为“待复核”的真实数据。
10. 用户可导出报告，报告包含生成时间、数据范围和风险依据。

### 5.3 恢复流程

1. 用户打开操作历史，选择某次备份操作。
2. 应用校验备份文件完整性和目标路径冲突。
3. 用户选择跳过、重命名或覆盖；默认禁止覆盖。
4. 恢复完成后输出逐文件结果，不允许以组数代替文件数。

## 6. 功能需求

### FR-01 工作区与环境诊断

**需求**：应用维护当前工作区、数据库位置、备份位置和服务状态。

**验收标准**：

- 首次启动无需打开命令行即可完成环境检查。
- 明确显示桌面后端、数据库、解析服务、AI 模型四项状态。
- AI 不可用时仍允许扫描、去重和非 AI 解析。
- 工作区切换不会混用其他项目数据。

### FR-02 安全文件扫描

**需求**：扫描范围准确、可控制、可中止，不因特殊目录或链接无限扩张。

**验收标准**：

- `.git`、`node_modules`、`target`、`__pycache__` 和应用备份目录被真正剪枝。
- 默认不跟随符号链接/目录联接；开启时必须警告。
- 权限错误、损坏路径和读取失败计入失败明细。
- 用户取消后 2 秒内停止新增任务，已完成结果可保留。
- 扫描不修改用户目录；清单写入应用数据目录或经用户明确同意的位置。

### FR-03 重复文件与版本分析

**需求**：区分“完全重复”和“版本候选”，避免将相似文件误当作可清理重复文件。

**验收标准**：

- 完全重复必须以全文件内容哈希为最终依据。
- 版本候选不得自动进入清理清单。
- 每组显示判断依据、推荐保留项及推荐理由。
- 同修改时间、哈希失败、文件变化等不确定情况必须阻止自动推荐。

### FR-04 安全备份与恢复

**需求**：移动操作可预览、可追踪、可原位恢复。

**验收标准**：

- 操作前列出所有源路径、目标路径、大小和预计释放空间。
- 备份保留相对目录结构，保存 `operation.json` 操作清单。
- 复制后校验大小与哈希，成功后才能删除源文件。
- 任一文件失败不回报整批成功；结果包括成功、失败、跳过。
- 默认禁止覆盖目标文件。
- 100% 恢复测试通过后，备份功能才可发布。

### FR-05 文档解析

**需求**：按支持矩阵解析文档，并完整记录处理状态。

| 格式 | v1.0 支持级别 | 说明 |
|---|---|---|
| PDF | 必须 | 文本 PDF；扫描 PDF 依赖 OCR |
| DOCX | 必须 | 正文和基础表格 |
| XLSX | 必须 | 工作表、单元格和值 |
| TXT/CSV | 必须 | UTF-8/常见中文编码 |
| JPG/PNG | 可选 | OCR 可用时处理 |
| DOC/XLS | 条件支持 | 转换器可用时处理，否则明确提示 |
| DWG/DXF | 元数据 | 不解析内容 |

**验收标准**：

- 每个文件有 `pending/running/succeeded/failed/skipped/cancelled` 状态。
- 失败记录错误码、可读信息和重试建议。
- 不支持格式明确标记为跳过，而不是失败或成功。
- 重复运行时，未变化且已成功的文件使用缓存。

### FR-06 字段抽取与人工复核

**需求**：AI 结果必须经过结构校验和可选人工确认。

**核心字段**：项目名称、合同编号、合同金额、甲方、乙方、签约日期、人工成本、材料成本、设备成本、分包金额、结算金额、结算日期、质保金比例。

**验收标准**：

- 金额、日期、比例进行格式和范围校验。
- 每个字段保存原始值、标准值、置信度、来源文件和来源片段。
- 同一字段多来源冲突时进入复核队列，不静默覆盖。
- 用户可编辑、确认、驳回；所有修改留审计记录。
- AI 服务不可用时提供规则抽取或“仅解析不抽取”模式。

### FR-07 项目聚合与风险计算

**需求**：只基于可追溯数据生成项目指标和风险。

**验收标准**：

- 聚合规则版本化，并记录每次运行时间和输入范围。
- 缺失数据不自动按 0 参与可能造成误导的计算。
- 风险结果保存规则编号、阈值、实际值、来源字段和计算时间。
- 用户能够从看板风险下钻到具体文件及字段。
- 风险规则单元测试覆盖边界值、空值和异常值。

### FR-08 看板与报告

**需求**：看板和报告准确表达数据状态，不用演示数据掩盖异常。

**验收标准**：

- 空数据库展示引导式空状态。
- 数据加载失败展示错误和重试，不显示模拟项目。
- 待复核数据具有清晰标识，默认不计入正式汇总或可切换查看。
- 报告包含数据截止时间、项目范围、缺失字段、待复核项和规则版本。
- 导出数据与屏幕筛选范围一致。

### FR-09 操作历史与日志

**需求**：用户能诊断“发生了什么”，维护者能定位失败原因。

**验收标准**：

- 记录扫描、解析、抽取、备份、恢复、ETL、导出操作。
- 日志默认不包含完整文档正文或模型输入。
- 用户可导出诊断包，包含版本、环境、脱敏日志和数据库完整性结果。
- 日志有大小上限和自动轮转。

## 7. 非功能需求

### 7.1 数据安全

- 默认本地处理，不上传文件或业务数据。
- Tauri 文件系统权限限制到用户选择目录和应用数据目录。
- 启用 CSP，禁止任意外部脚本和非必要网络访问。
- 数据库启用外键、WAL 和事务；启动时执行完整性检查。
- 升级和迁移前自动备份数据库。

### 7.2 性能基线

| 场景 | 验收目标 | 测试条件 |
|---|---|---|
| 1 万文件元数据扫描 | ≤ 60 秒 | 本地 SSD，不含哈希 |
| 1 万个小文件哈希 | ≤ 10 分钟 | 可取消，内存 ≤ 800 MB |
| 1000 项目看板首屏 | ≤ 2 秒 | 已建索引的本地数据库 |
| 5000 行表格筛选 | ≤ 300 ms | 常规办公电脑 |
| 空闲内存 | ≤ 300 MB | 不加载 AI 模型 |

性能目标必须通过基准数据验证，不得继续在文档中使用未经测试的“10 万文件 5 分钟”等承诺。

### 7.3 可靠性与兼容性

- 支持 Windows 10 22H2、Windows 11 当前受支持版本。
- 应用异常退出后，重启可识别未完成任务并安全恢复或重新开始。
- 单文件失败不应终止整批任务。
- 安装包必须包含或检查全部运行依赖，不要求用户安装 Node/Rust。
- Python/AI 依赖采用内置运行时或安装器管理，不能依赖用户全局 Python。

## 8. 数据与状态规范

### 8.1 数据真实性标签

所有页面使用统一数据状态：

- `confirmed`：用户确认或确定性规则生成，可计入正式报表。
- `extracted`：自动抽取但未复核，必须标记。
- `conflicted`：多来源冲突，不计入正式汇总。
- `missing`：缺失，不得伪造为 0。
- `demo`：仅演示模式存在，不能写入生产工作区。

### 8.2 任务状态

批处理统一采用：`queued → running → succeeded/partial/failed/cancelled`。任务汇总必须同时报告总数、成功、失败、跳过和取消数量。

## 9. 版本计划

| 阶段 | 目标 | 主要交付物 | 建议周期 | 退出条件 |
|---|---|---|---|---|
| R0 止血 | 能构建、无明显数据破坏 | 统一 Tauri、接口、数据库写入和备份设计 | 1–2 周 | P0 全关闭，桌面构建通过 |
| R1 真链路 | 真实样本可跑通 | 扫描到看板端到端流程、错误明细 | 2 周 | 黄金样本 E2E 通过 |
| R2 可操作 | 业务人员可复核使用 | 人工复核、来源追溯、操作历史 | 2 周 | 试点用户完成任务 |
| R3 可交付 | 可安装、升级和支持 | 安装包、迁移、诊断、文档、发布门禁 | 1–2 周 | 发布清单全部通过 |
| R4 试点稳定 | 真实项目稳定使用 | 性能优化和缺陷收敛 | 2–4 周 | 连续 10 个工作日无 P0/P1 |

周期为单人全职开发的粗略建议；正式排期应在技术方案评审后调整。

## 10. 上线门槛

以下条件全部满足才允许标记“真实可用 v1.0”：

- 全新 Windows 测试机可用安装包完成安装和启动。
- 前端构建、Rust 构建、单元测试、集成测试全部通过。
- 真实样本端到端成功率达到约定标准，失败均有明细。
- 生产代码路径无自动 mock 回退。
- 备份恢复覆盖同名文件、嵌套目录、中断和磁盘不足场景。
- SQLite `foreign_key_check` 和 `integrity_check` 通过。
- 不存在未关闭的 P0/P1 缺陷。
- 使用手册、故障排查、数据备份恢复说明与实际版本一致。
- 产品负责人、技术负责人和至少 1 名试点用户签字验收。

## 11. 验收样本集

建立不含敏感信息的固定“黄金样本库”：

- 100–300 个文件，覆盖嵌套目录、中文路径、长路径和同名文件。
- 至少 5 组完全重复、5 组版本候选、3 个哈希/读取失败场景。
- 至少 10 份合同、10 份成本表、5 份结算文件和 5 份扫描 PDF。
- 为核心字段维护人工标注真值。
- 每次发布运行同一数据集并保存结果差异。

## 13. 评审决策项

开发前需确认：

1. Tauri 统一采用 v1 维护线还是升级到 v2；建议优先升级 v2，但需单独评估迁移成本。
2. Python/AI 是随安装包内置，还是独立可选组件；生产环境不接受依赖全局 Python。
3. v1.0 是否必须支持图片 OCR；若时间有限，可作为可选组件发布。
4. 人工复核后的字段是否才允许进入正式报表；本 PRD 默认“是”。
5. 备份保留策略和磁盘空间上限。
